# ADR 0002: Tauri capability and command boundary

- Status: Accepted renderer boundary; the listed command set is the historical M0 surface and later commands are governed by ADRs 0007–0009
- Decision: Treat the webview renderer as untrusted. Expose payload-free `system_get_info` in every build. Compile the runtime-smoke command and handler only with debug assertions; release binaries must contain neither the command nor its environment seam. In debug builds, accept only the backend-derived platform/version marker and a create-new `renderer-ready` path in a canonical mode-0700 `paprv-runtime-smoke-*` child of the system temp directory, then append the Rust process PID. The runner verifies that PID's executable is the expected bundle before terminating it. Validate system info again with Zod in the renderer. Bind the sole capability to the `main` window with an empty plugin/core permissions list. Create that webview manually so production navigation is restricted to `tauri://localhost`, development navigation to exact `http://127.0.0.1:1420`, and all new-window requests are denied. At M0, no shell, HTTP, filesystem, dialog, updater, remote URL, or additional-window plugin permissions were enabled. Current paper, document, Study, and generation behavior uses closed typed Rust commands without widening that plugin permission set. Enforce a strict CSP from Tauri configuration.
- Consequences: The renderer cannot directly access files, SQLite, credentials, network plugins, or process APIs. Every future command or permission requires a security review, typed input validation, and negative tests.
