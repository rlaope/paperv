# ADR 0009: Separate Paper Study from the Markdown Vault

- Status: Accepted
- Decision: Paprv has two peer workspaces. **Library → Study** owns imported paper metadata, the stored arXiv abstract, a Claude-like natural-request composer, ephemeral conversational generation state, and explicitly saved AI artifacts. **Vault** owns any number of independent Markdown documents in an editor-first native-textarea surface. A paper never owns a Markdown document, and an AI result never writes to one automatically. Explicit many-to-many edge records connect documents to papers or saved Study artifacts. Backlinks are derived from these edge records rather than Markdown regexes.
- Migration: SQLite v3 atomically converts every legacy `notes` row into one independent document with ID `legacy-note:<arxiv-id>`, preserves its Markdown and timestamps byte-for-byte, and creates one explicit paper link plus a migration-origin record. SQLite v4 adds immutable artifact source-document identity snapshots so provenance survives deletion of the live document row. These snapshots preserve identity, not the source revision text. SQLite v5 extends the artifact-level constraint with `technical_polish` and requires a document or document-selection source. The legacy table is dropped only after count and constraint checks succeed. Developer downgrades are permitted only when every value removed by a step is representable without loss. Any `technical_polish` artifact blocks v5→v4; populated identity snapshots block v4→v3; renamed or modified migrated documents, additional links, or artifacts block v3→v2 without changing data.
- Consequences: Duplicate document titles are allowed; Rust-generated IDs identify documents. Document saves use integer revision-based optimistic concurrency and retain the existing 262,144 UTF-8-byte limit. Users may create documents with no paper, connect one document to many papers/artifacts, and connect many documents to one paper/artifact. Reimporting a paper updates only paper metadata. The desktop UI exposes Library and Vault in the activity ribbon, keeps mixed Study/document tabs, presents generation only in Study, and uses an explicit Properties/Backlinks inspector. The Vault document surface has a subtle inline breadcrumb/name input and no visible Title/status, Edit/Preview, formatting, revision, word-count, or normal-save chrome; autosave remains aria-live, with visible recovery only for error or conflict. Study uses compact Agent and Context controls, keeps readiness internal unless remediation and Retry are needed, and has no always-visible readiness table or task/source/language radios. One natural request triggers one closed skill/language selection, not arbitrary agent tools. The request is ephemeral and absent from storage and returned run/artifact metadata. Generation previews do not mutate documents; artifact save and artifact-to-document linking remain separate explicit actions. Selected skill/language continue in SQLite v5 artifact fields, so this UI change adds no v6. Folder hierarchy is deferred rather than simulated in the current schema.
