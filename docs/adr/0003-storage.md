# ADR 0003: Rust-owned SQLite storage

- Status: Accepted; revised by ADR 0006 and ADR 0009
- Decision: Use `rusqlite` with bundled SQLite in Rust. Migrations are ordered, transactional, reversible only when lossless, and fail closed on unknown versions, gaps, ledger drift, canonical table/index drift, or partially applied state. The renderer has no database API. SQLite v3 separates paper Study records from independent Markdown documents and stores document–paper and document–artifact relationships as explicit edges. SQLite v4 adds immutable source-document identity snapshots for saved artifacts. SQLite v5 adds the closed `technical_polish` level and rejects it unless the source kind is `document` or `document_selection`. Legacy paper-owned notes migrate atomically into independent documents plus paper edges.
- Consequences: Rust-generated IDs identify documents and artifacts; duplicate titles are allowed. Document writes enforce UTF-8 byte limits and optimistic integer revisions. Paper reimport cannot mutate documents, artifacts, or links. Saved generation artifacts require explicit user action and do not create edges. A source snapshot preserves only document identity; the artifact row separately stores bounded revision/range provenance, and neither stores revision text. Downgrading v5 to v4 is lossless only when no `technical_polish` artifact exists. Existing provider-setting types accept only closed provider IDs and canonical keychain-reference UUIDs; raw credentials remain rejected. Detailed schema and downgrade invariants are in [`0009-study-and-vault.md`](0009-study-and-vault.md) and [`../design/study-vault-generation.md`](../design/study-vault-generation.md).
