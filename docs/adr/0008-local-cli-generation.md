# ADR 0008: Isolated local CLI generation for Study artifacts

- Status: Accepted; revised by ADR 0009
- Decision: Paprv may generate Markdown previews through a user-installed local CLI behind a provider-neutral Rust boundary. Generation belongs to Study, not the Vault editor. A dense Claude-like composer accepts a natural request and compact Agent and Context selections; it does not expose Task, Source, or Output-language fieldsets. The trimmed request must be non-empty, at most 4096 UTF-8 bytes, and control-safe. One Claude invocation selects exactly one closed skill (`translate_structure`, `explain_simply`, or `technical_deep_dive`; document-backed sources may also select `technical_polish`) and English or Korean, then generates Markdown. This is request-intent classification inside a closed generation contract, not arbitrary shell or tool dispatch. Results remain ephemeral until the user explicitly saves one as a Study artifact; artifact linking is another explicit action. Generation, saving, and linking never mutate a Markdown document implicitly. Claude Code is currently generation-capable. Codex CLI remains a disabled discovery-only option. Claude's direct argv includes an empty `--tools` value and `--disallowedTools '*'`, plus strict empty MCP, disabled slash commands/browser/session persistence, `dontAsk`, one turn, and source-specific schema-constrained JSON output. The abstract schema excludes `technical_polish`. The authentication probe is exactly `claude auth status`; Paprv uses only the exit status and ignores the body. Codex is never spawned because its official CLI reference does not document an all-tools-off contract.
- Consequences: Public readiness probes and generation share one app-owned fail-fast admission, cancellation, process-group settlement, and shutdown lifecycle. Normal composer UI keeps readiness internal; only brief unavailable/remediation copy and Retry appear when needed. If the first bounded absence proof expires, Rust retains the exact child/group and monitors it until leader settlement and full group absence are proven; persistent groups continue to block shutdown. Rust resolves the selected source from SQLite and sends it beside the request only through provider stdin, runs only the allowlisted CLI in a private empty temporary directory with a bounded environment, owns timeout/cancellation/output limits, and returns closed typed states without raw provider errors. The request exists only while the dialog is open and is never saved, logged, or returned in a run DTO, artifact, summary, or result metadata. `technical_polish` accepts only a saved document or exact selection and rejects a result with `result_preservation_failed` when deterministic code/math/citation/URL/DOI span checks fail. Rust validates every selected skill/language and Markdown result. The selected skill and language use existing SQLite v5 artifact fields; no v6 migration is required. Paprv never bundles a model, collects credentials, accepts executable paths or source text from the renderer, invokes a shell, or runs an agent in the repository or app-data directory. Saved artifacts retain bounded provenance but no request, source text, prompt envelope, stderr, path, auth detail, or raw provider envelope. Progress, errors, result Markdown, and safe metadata are conversational assistant content. Generated content is always marked as a study aid rather than paper evidence.
- Residual dependency: Claude's no-tools flags remove model-visible tools, but organization-managed hooks can remain active and cannot be disabled outside managed settings. Paprv therefore treats the installed CLI and managed policy as a trusted local dependency rather than claiming complete sandboxing.
