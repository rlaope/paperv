# Paprv threat model

## Trust boundary and assets

Assets include imported paper metadata, independent Markdown documents, explicit document links, saved Study artifacts, provider-login state owned by external CLIs, and usage metadata. The React webview is untrusted relative to Rust. Production loads only the local `tauri://localhost` asset origin; development allows exactly `http://127.0.0.1:1420`. Rust owns SQLite, arXiv network access, local CLI execution, and typed command validation.

| Threat | Impact | Control | Evidence |
| --- | --- | --- | --- |
| Webview compromise reaches native APIs | File or credential theft | Main-window capability has no permissions; no shell/http/fs/dialog/updater plugins; closed typed commands only | Capability/config tests and command-schema tests |
| Hostile remote navigation/content | Renderer replacement | Exact local origins, top-level navigation allowlist, every new window denied, strict self-only CSP | Navigation/config tests and runtime smoke |
| Migration corruption or product-model drift | Document loss | Canonical transactional v0→v5 migrations; atomic legacy-note conversion; immutable artifact source identity snapshots; closed technical-polish source constraint; unknown/gap/partial schema fail closed; any lossy downgrade rejected | Migration matrix, rollback, count, Unicode, provenance and drift tests |
| Reimport overwrites user work | Local-data loss | Paper upsert changes paper metadata only and preserves independent documents, Study artifacts, and explicit links | Storage preservation tests |
| Lost update across multiple documents | User-writing loss | Integer optimistic revisions, serialized writes per document, stale-response guards, flush-before-close/delete, conflict recovery | Rust revision and renderer draft-race tests |
| Generated output mutates a document | Unreviewed content/data loss | Generation is Study-only and memory-only until explicit Save artifact; no generation command can create/update a document or edge | Storage side-effect and UI workflow tests |
| Generated text appears as paper evidence | Misleading learning record | Permanent study-aid provenance, separate Study surface, no automatic Evidence/Backlink insertion | Evaluation fixtures and rendered UI review |
| Malicious paper/document text controls the host agent | File/secret disclosure | Source is untrusted data sent only over stdin; Claude uses direct argv with an empty `--tools` value, `--disallowedTools '*'`, empty MCP, no session persistence, a private empty cwd, and a bounded allowlisted environment; Codex generation is blocked | Exact argv/stdin/env/cwd and Codex fail-closed tests |
| CLI configuration, managed hooks, or repository instructions are ingested | Privilege expansion | Every readiness probe and generation run uses a fresh private mode-0700 cwd/TMPDIR and never runs in repository/app-data/paper paths. Strict flags remove model-visible tools and local MCP/session surfaces. Managed hooks remain a trusted local-policy residual because they cannot be disabled outside managed settings | Fake-provider process tests, argv review, and documented residual risk |
| Detached or racing readiness process | Orphan process, stale enablement, or shutdown hang | Public readiness and generation share one app-owned fail-fast admission lane, exact cancellation signal, process-group settlement, closed lifecycle, and shutdown wait | Readiness/generation concurrency, cancellation, eventual-settlement, and shutdown tests |
| Child timeout/cancel leaves descendants | Persistent process or continued data handling | Owned process group, concurrent bounded pipe drains, one-second TERM grace, unconditional SIGKILL fallback despite intermediate errors, separate five-second absence proof, leader reap, and shutdown cancellation. An initial proof timeout retains the exact child/group in a settlement monitor; persistent groups keep shutdown blocked, while later proven absence releases only the matching operation | Flood/timeout/cancel/process-tree/eventual-absence tests plus orphan scans |
| Provider output or errors leak source/auth/path | Confidentiality loss | Closed errors; bounded schema-only success; no raw stdout/stderr/path/auth/prompt/source/result logging | Protocol/redaction tests and static review |
| Natural request leaks or becomes arbitrary agent dispatch | Confidentiality loss or host actions | Trimmed non-empty request is capped at 4096 UTF-8 bytes and rejects unsafe controls; it travels only on provider stdin beside separately Rust-resolved source. Fixed instructions and source-specific schemas allow one closed skill and English/Korean, with no tool, shell, slash-command, or arbitrary-skill path. Request text is absent from logs, storage, run DTOs, artifacts, summaries, and result metadata | Request-boundary, exact-stdin, closed-schema, DTO and persistence tests |
| Technical polishing drops protected code/math or changes reference spans | Broken code/math/references or injected links | `technical_polish` accepts only document-backed sources, requires every source code/math span with its multiplicity, and requires exact citation/URL/DOI spans before exposing a preview; failure closes as `result_preservation_failed` | Preservation fixtures with missing/changed code or math and missing/novel reference spans |
| Technical polishing is mistaken for verification | Unsupported trust in claims or citations | UI labels the result as an AI-polished preview, states that Vault is unchanged, and makes no claim-level or citation-support assertion | Copy contract and evaluation review |
| Conversational metadata leaks hidden source/provider details | Confidentiality loss | Assistant metadata is derived only from validated result state and safe document labels; it excludes request/source text, raw paths, document/run IDs, offsets, auth, prompts, and provider I/O | Renderer metadata and request-absence tests |
| Executable/path injection | Arbitrary code execution | Fixed provider identity, validated absolute PATH directories, non-group/world-writable regular executable, no renderer path/argv/cwd/env/model fields, no shell | Discovery rejection and IPC closure tests |
| Hostile arXiv reference or endpoint | SSRF or unexpected origin | Strict canonical ID/URL parsing, fixed HTTPS export endpoint, no redirects or caller endpoint | Identifier/client tests |
| Hostile Atom response | Metadata corruption or memory pressure | 256 KiB cap, DTD rejection, one matching entry, strict UTF-8/timestamp/cardinality/field bounds | Fixture and bounded live-import tests |
| Unsafe generated Markdown | Script execution or navigation | Generated Study result uses `react-markdown` + `remark-gfm`, raw HTML disabled, external navigation inert. The Vault has no document Preview mode | Unit/a11y/runtime checks |
| False-green packaged renderer | Shipping broken desktop app | Backend-derived readiness marker, exact bundle process identity, debug-only smoke seam removed from release | Runtime, concurrent runtime and release-smoke gates |

## Data and privacy rules

Paprv does not collect API keys, OAuth tokens, or subscription credentials. Users install and authenticate provider CLIs independently. The Claude authentication probe is exactly `claude auth status`; only exit status is interpreted and its body is ignored. Environment values needed for normal CLI/keychain discovery are allowlisted but never persisted or returned. The natural request is ephemeral to the open dialog and appears only in provider stdin; generation request/source text, selections, raw prompt/provider envelopes, stderr, executable paths, cwd, auth details, failures, and conversational UI state are not stored or returned. An explicitly saved artifact contains only validated generated Markdown plus bounded paper/provider/selected-skill/language/source-revision provenance in the existing SQLite v5 fields. A source snapshot preserves document identity, not revision text. Creating an artifact never creates a document link.

## Product boundaries and residual risk

Paprv currently imports arXiv metadata, not PDF bodies. PDF upload/download/viewing/parsing, whole-paper claims, remote collaboration, code signing, notarization, sandbox entitlements, updater safety, and release distribution remain separate work. The installed Claude Code executable, upstream service, and organization-managed policy are trusted local dependencies; Paprv limits invocation but does not attest them. Codex remains visible but generation is disabled because its official CLI reference does not document an all-tools-off contract. Technical span preservation is deterministic but cannot establish factual correctness or that a citation supports a claim.
