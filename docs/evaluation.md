# Human evaluation protocol

The machine-readable blind rubric is `tests/fixtures/evaluation/human-rubric.json`. Randomize output order, hide system identity, and use two independent reviewers. Reviewers score accuracy, evidence, flow, difficulty, and professional/non-formulaic style from 1–5 using anchored definitions. Record disagreements before reconciliation; do not replace human review with a phrase blacklist. The five-paper corpus is metadata-only and contains no copyrighted PDFs or article text.

Paprv imports bounded arXiv metadata and can generate Study previews through the separately approved local Claude CLI boundary. `test:eval` validates fixture, disclosure, closed-error, and rubric contracts rather than provider output quality. Human scoring becomes an execution gate only when a release candidate includes a consented authenticated-provider evaluation run against the fixed corpus; local credentials and copyrighted paper text are never stored in the fixtures.

Composer evaluation begins with natural requests rather than preselected task/language radios. Each case verifies that one invocation returns exactly one allowed skill and one of English/Korean, that abstract cases can never return `technical_polish`, and that document-backed polish requests still pass Rust preservation checks. Include intent paraphrases, ambiguous-language requests, over-4096-byte input, empty/whitespace input, unsafe controls, and attempts to request tools, shell commands, arbitrary skills, or full-paper access. The latter are data for closed skill selection, never dispatch instructions.

Privacy assertions verify that the trimmed request is present only in the provider stdin envelope beside the separately Rust-resolved source. It must be absent from fixed logs, `generation_start` and run DTOs, success/error metadata, artifact rows and DTOs, conversational assistant metadata, and any summary. The selected skill and language may persist only through the existing SQLite v5 artifact fields.

Technical-polish evaluation uses saved synthetic Markdown or an exact synthetic selection. The machine gate requires every source fenced/inline code and supported math span with its source multiplicity. Citation commands and keys, URLs, and DOIs must match exactly, so missing or novel reference spans close as `result_preservation_failed`. Reviewers separately score clarity and meaning preservation. Passing the span gate does not prove factual correctness, validate a claim, or show that a citation supports nearby prose. The evaluated result remains a preview unless explicitly saved as a Study artifact, and saving does not link it to a Vault document.

Interface evaluation checks the dense Claude-like composer with compact Agent and Context selects, disabled discovery-only Codex, no provider readiness table in the ready state, and only brief remediation plus Retry when unavailable. It also checks the editor-first Vault surface: native textarea, inline breadcrumb/name input, no Title/status/Edit/Preview/formatting/revision/word-count chrome, hidden aria-live normal saves, and visible recovery only on error or conflict. Raw-HTML and external-link cases target generated Study Markdown preview, not a removed document Preview mode.
